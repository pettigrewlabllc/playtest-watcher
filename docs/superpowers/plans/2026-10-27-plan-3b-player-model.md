# Plan 3b: Player model v1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. TDD per task, commit per task.

**Goal:** Replace the fingerprint-plus-per-kid-classifier with the player model in spec section 3b (including "Revisions from prior work" and "What the first debriefs taught us"): computed traits with ranges and game adjustment, an AFM skill and learning-rate model, two reaction-model variants scored under leave-one-game-out, a simulated-playthrough predictor, and the reliability and ranking checks.

**Architecture:** The modelling moves into Python (`analysis/`, venv at `analysis/.venv`, add `statsmodels` and `scipy` to `requirements.txt`), fed by the Node row builder (`src/predict/rows.ts`), which gains the new situation features. Node wrappers in `src/predict/` call the Python CLIs and keep the existing CLI (`npm run predict -- ...`) working. Existing predictors and scoring (`predict.ts`, `score.ts`) are extended, not rewritten.

## Global Constraints

- Everything in Plan 3's Global Constraints still holds (no kid names in the repo, fake Meta client only, temp roots in tests, never the word "personality").
- Inputs per kid also include `recordings/kids/<letter>/debriefs.json` (array of `{ game, session, answers: [{ q, a, fun?, intent? }] }`), `ranking.json` (`{ order: string[] }`), and `recordings/kids.json` (`{ <LETTER>: { age, learn, check } }`, names are present there: never copy them into outputs).
- Every trait output is `{ value: number|null, lo: number|null, hi: number|null, n: number, games: string[], adjusted: boolean, source: string }`. `lo`/`hi` are a 90% interval. Never NaN.
- Shrinkage: a kid's per-game trait value is pulled toward the mean of all kids on that game with weight `n / (n + k)`, k = 5 observations (state `k` in the output).
- Games are compared only with other kids on the same game. With fewer than 2 kids on a game, `adjusted: false`.

## Task 1: Situation features (rows.ts)

Add to every row: `prev_label` (label of the most recent moment that ended before this event, else `none`), `s_since_moment`, `rapid_retry` (1 if an attempt comes < 1 s after a fail), `attempts_no_success` (attempts since the last success, the wheel-spinning count), and `intent` (from debriefs: an event type the kid called accidental gets `intent: 'accidental'`). Tests: each feature on a hand-built session, including a debrief that marks `compendium_open` accidental.

Changed during build: rows also carry `kid` and `block` (a new block at every `*_start` progress event except `logger_start`, falling back to progress events with a level, wave or season when a session has fewer than two; block 0 is everything before the first). A fail within 50 ms of the previous fail is the same failure and no longer adds to `fail_streak` (Factor Slicer logs `wrong_cut` and `life_lost` at the same instant, which doubled every streak). `s_since_moment` is seconds since the session started when no moment has ended yet. Debrief answers name their event with an optional `event` field (an event type); without it, an answer's intent applies to event types whose 5+ letter name tokens start a word in the question or answer ("Compendium" matches `compendium_open`). The real Bond Swap answer doesn't resolve: the Compendium event is logged as `entry_view`, so that answer needs `"event": "entry_view"` added by hand. With no moments (weak labels), `prev_label` stays `none`.

## Task 2: AFM skill and learning rate (analysis/afm.py)

`afm.py --rows all_rows.csv --out afm.json`. Rows are attempts with success outcomes (an `attempt` followed by `success` or `fail` of the same type within 2 s; unresolved attempts dropped). Practice = the kid's count of prior attempts on that game. Model: `logit P(success) ~ C(kid) + C(game) + C(game):practice + C(kid):practice` with L2 (sklearn LogisticRegression, C chosen by grouped CV over sessions). Output per kid and game: skill (kid + game intercept), learning rate (practice slope), each with a 90% interval from 200 bootstrap resamples **by run or level block**. pytest: a synthetic set with a planted fast learner and slow learner recovers the order of their slopes and their intervals don't overlap.

Changed during build: an attempt pairs with the first `success`/`fail` within 2 s **after it and before the next attempt**, preferring one of its own type, not only one of the same type: Factor Slicer's outcome of a `slice` is `slice_ok` or `wrong_cut`, so the same-type rule would have dropped every attempt in that game. Practice counts all of the kid's earlier attempts on the game, resolved or not, in units of 10 attempts (so the L2 penalty bites on the slopes at a sensible scale). C is chosen from {0.01, 0.1, 1, 10} by log loss under grouped 5-fold CV over **(session, block)** groups, not over sessions: with one kid on a game, holding out the session removes that kid-game cell entirely, so session CV would score transfer to an unseen cell rather than fit. Bootstrap resamples blocks within each session (so each session keeps its size) and refits at the chosen C. Skill is log-odds at practice 0; learning rate is log-odds per 10 attempts; both carry `blocks` (how many blocks the cell rests on). Where only one kid plays a game, kid and game terms aren't separately identified (only their sum is), so `adjusted: false` and the `kid_term` there is the penalty's split, not evidence. `scipy` and `statsmodels` are in `requirements.txt` as planned; nothing needed `statsmodels` in the end. Shared helpers (trait shape, percentile interval, block resampling, NaN-free JSON) live in `analysis/common.py`.

## Task 3: Trait estimators (analysis/traits.py)

`traits.py --sessions <dirs...> --kids kids.json --afm afm.json --out traits.json` producing per kid: the ten traits of spec 3b (frustration tolerance as k50 from a logistic of negative-moment-within-10 s against fail streak, recovery, learning rate and skill from AFM, persistence including wheel-spinning, exploration drive discounting accidental events, reading, pace, challenge appetite, stamina with the mood tap, expressiveness), plus `confusion_resolves` (share of confused moments followed by `none` or `delighted` rather than `frustrated` within 30 s), plus `said` values from the questionnaire and debrief fun scores, plus `gaps` where said and did disagree beyond the interval. Bootstrap intervals by run or level block; shrinkage and game adjustment per the constraints. pytest per trait on synthetic sessions, plus: an events-only session (no moments) yields nulls for moment-based traits, never errors.

Node: `src/predict/traits.ts` wraps it; `fingerprint.ts` stays only as the per-session feature source.

Changed during build:
- Output is one `traits.json` for all kids (game adjustment needs everyone), written with `afm.json` and `all_rows.csv` to `recordings/group/` by `buildGroupModel` / `npm run predict -- traits`. `forget` deletes `group/` (it pools the forgotten kid's rows), to be rebuilt. Per kid, each trait is a top-level entry plus `per_game`. Per game: `value` is the shrunk value in natural units, with `raw`, `group_mean`, `weight` (= n/(n+5) when adjusted, 1 otherwise) and `n_unit`. Top level: the n-weighted mean over adjusted games of the difference from the group mean on that game; **null when the kid shares no game with another kid** (raw numbers from different games aren't comparable). AFM skill and learning rate come from `afm.json` (its own L2 is their shrinkage; no second k = 5 pull); the top-level AFM values are the kid term and kid slope, null where no game is shared, because then they aren't identified.
- n is counted in each trait's natural unit (fails, failed runs, texts, minutes for rates, moments), so k = 5 means "five of those". A fixed k is a prior, not an estimate: with two kids per game the between-kid variance can't be estimated, so true empirical Bayes isn't possible yet.
- Intervals: block bootstrap within each session; the group mean is bootstrapped in step from each kid's own replicates (so a difference from the group carries the other kid's uncertainty too); the interval is widened to contain the point estimate and to be no narrower than the exact Poisson (rates) or Clopper-Pearson (shares) interval, because a block bootstrap collapses to a point when every block agrees (zero explore events gave [0.18, 0.18] on real data). The top-level interval is also no narrower than the per-game intervals carried through the same weights (conservative when there are 2+ games).
- Frustration tolerance labels a fail as upsetting if a frustrated or stuck moment is active at it or **starts before the next fail** (within 10 s): with fails 1 to 2 s apart, a plain 10 s look-ahead credits frustration to fails several steps earlier and pulls k50 down. k50 is null when the streak slope isn't positive or k50 is beyond twice the longest streak (`censored_at` then says the longest streak seen without crossing).
- Concrete definitions: a run is a block (see Task 1); a failed run is one whose last outcome is a fail; wheel-spinning is attempts made with 10+ attempts since the last success (`wheel_spin_share`); challenge appetite is P(bored active or starting within 10 s) at successes with a streak of 5+, without the "no new_thing for 60 s" half; stamina's value is the slope of negative moments (frustrated, stuck, bored) per minute across blocks, with the events-only attempts-per-minute slope and the mood taps beside it; expressiveness is the mean share of face/voice/hands with evidence, plus talk per minute when a transcript exists. Events after `debrief_start` or after the recording stopped (`durationMs`) are left out. Questionnaire axes map to traits (explore, read, challenge, persist, social, pace; -1 is the "more" end); a gap is listed when |said| >= 0.5 and the adjusted interval lies entirely on the other side of the group mean.

## Task 4: Two reaction-model variants and baselines (analysis/reaction.py)

Training data: rows from **all kids' learn sessions**. Variant `traits`: situation features + the kid's trait values (game-adjusted, shrunk) + traits × fail_streak and × s_since_success interactions. Variant `kid`: situation features + kid one-hot + kid × the same two situation features. Both L2 multinomial logistic. Baselines: `base_rate` (label rates by minute of session) and `markov` (first-order transitions from `prev_label`). Leave-one-game-out: hold out **every** kid's rows for the target game. Metrics per variant and baseline: macro-F1, per-label AUC (one-vs-rest), Cohen's kappa, label-mix total-variation distance. Output `reaction.json` and models. pytest: on synthetic data where the reaction depends on a trait (high-tolerance kids frustrate later), `traits` beats `base_rate` under LOGO; the held-out game never appears in a fold's training rows.

Changed during build:
- **Traits are recomputed inside each fold without the held-out game** (`traits.compute` on the other games' sessions). Using `traits.json` built from everything would leak the target game's labels into moment-based traits like frustration tolerance. The trait features are the top-level (game-adjusted, shrunk) values of the nine non-AFM traits except stamina; a null trait is 0, which is the group. AFM skill and learning rate are left out of the reaction features: per-kid AFM terms aren't identified for a kid who shares no game, and the situation features already carry in-the-moment success (fail streak, wheel-spinning count). Simulation (Task 5) is where skill enters.
- Situation features: Plan 3's nine numerics and event kind, plus `rapid_retry`, `attempts_no_success`, `s_since_moment` and a one-hot `prev_label`.
- No class weighting (probabilities need to stay calibrated, since simulation averages them and the scoreboard compares label mixes); a label with fewer than 10 training rows in a fold isn't modelled there (probability 0) rather than letting a handful of rows dominate a multinomial fit. C = 1.0 on standardized features for both variants, fixed rather than tuned, so the comparison between them is like for like.
- Baselines: `base_rate` is the label mix per minute of session, `markov` is the mix per `prev_label`; both smoothed toward the overall training mix with 10 pseudo-rows. Metrics are reported per fold and pooled over all held-out rows; the label-mix distance compares the mean predicted probabilities with the real mix. `reaction.json` also records `weak_labels` (true when any session had no `moments.json`, in which case labels are the fail-streak/idle heuristic and the model is learning that heuristic back).
- Node: `src/predict/reaction.ts` (`fitReaction`) and `npm run predict -- reaction`; outputs in `recordings/group/reaction/`. A pytest also checks the traits carry the difference: with every kid's traits set to the group, the traits variant drops by more than 0.05 macro-F1. Python has its own row builder (`analysis/situation.py`, mirroring `rows.ts`, checked against the same hand-built session) because simulation must recompute features as it goes.

## Task 5: Simulated-playthrough predictor (analysis/simulate.py + predict.ts)

For a kid and a target session (a reference playthrough): keep its sequence of stages and attempts, resample each attempt's success from the kid's AFM skill for that game (games the kid hasn't played use the kid's skill shrunk to the group mean for that game, which the other kids' data provides), recompute situation features along the simulated path (fail streaks, wheel-spinning, prev_label from the model's own sampled reactions), and run both variants; 200 simulations; per stage, mean probability per label. Emit `prediction-model-traits.json` and `prediction-model-kid.json` in the existing `Prediction` shape so `score.ts` works unchanged. pytest: a high-skill kid gets fewer predicted frustrated moments than a low-skill kid on the same reference.

Changed during build: files are `model-traits.json` and `model-kid.json` (the existing `<predictor>.json` convention of `writePredictions`), predictor names `model-traits` and `model-kid` (`MODEL_VARIANTS`, `ALL_PREDICTORS` in `predict.ts`). `simulate.py --models <group>/reaction --afm <group>/afm.json --kid L --target <dir> --out <dir> [--n 200]` writes `probs-traits.csv`, `probs-kid.csv` (mean probability per reference event) and `simulation.json`; `simulateVariants` in `predict.ts` turns them into predictions with the same stage rule as the `model` predictor (shared as `itemsFromProbs`). Attempts pair with outcomes as in the AFM; a consequence fail logged at the same instant (`life_lost` after `wrong_cut`) disappears in a simulation where that attempt succeeds, and a flipped outcome takes the reference's most common success or fail type for that attempt type. Practice starts at 0 on the target (the use case is a game the kid hasn't played). P(success) uses the AFM coefficients: for a game no kid has played, the game terms are 0 (an average game); for a kid without AFM data, the kid terms are 0 (the group). Outcome draws are shared by both variants so they see the same simulated playthroughs. Simulated reactions feed `prev_label`: a sampled run of one non-none label is a moment that ends when the label changes. `npm run predict -- predict` adds both variants when `recordings/group/reaction/models.joblib` exists. Stage/type cells are read back from CSV without quoting, which is safe for game event names (no commas) but not general.

## Task 6: Reliability, ranking and fidelity in scoring

- `labels.json` per session (Joel's hand labels: `{ momentId: label }`); `npm run predict -- reliability` computes Cohen's kappa between Joel and Muse overall and per label across all labelled moments, and the scoreboard prints it **above** every prediction score, with a warning when below 0.6.
- Ranking check: for each kid with `ranking.json`, compare the model's predicted enjoyment order (mean P(delighted) − P(bored or frustrated) per game) with the kid's order; report Kendall's tau.
- Scoreboard adds per-label AUC, kappa and label-mix distance for each predictor, and both model variants.

Changed during build:
- Reliability lives in `src/predict/reliability.ts`. Joel's labels pair with that session's `ok` Muse moments by id; ids with no Muse moment are skipped. Per-label kappa is one-vs-rest. With no hand labels the scoreboard says so on its first line (every score then rests on unchecked Muse labels); kappa null or below 0.6 prints a WARNING line. `npm run predict -- reliability` prints just that; `logo` prints it too.
- Predictions are item lists (stage, event type, label, p), not per-event probabilities, so the new metrics are **stage-level**: kappa between the top-p predicted label per stage and the most common real label per stage (`none` when empty), and per-label AUC of the item p (0 when absent) for "this label happens at this stage", over the real session's stages. `mix_distance` = 1 - mix similarity. Per-event AUC and kappa for the reaction model itself are in `reaction.json` (Task 4). `replayCeiling` now passes each real moment's confidence as its p.
- Leave-one-game-out runs the two variants (when the venv exists) from a fold group model (`group/logo/<game>-<hash>/`: rows, AFM without bootstrap, `reaction.py --final-only`) built from every kid's learn sessions except that game, cached by the training-session ids. Each fold records the variants' predicted enjoyment (mean P(delighted) - P(bored) - P(frustrated) over the simulated playthrough, carried on the prediction as `enjoyment`).
- Ranking: Kendall's tau (pairs with tied predictions count as neither) between `ranking.json`'s order and the LOGO enjoyment of each game, per variant; only games with a fold prediction count, and two games give only +1 or -1, which is a coin flip's worth of evidence. Printed under each player.
- `freeze` also freezes `model-traits` and `model-kid` when `group/reaction/models.joblib` exists; frozen-hash verification requires the four Plan 3 predictors and checks a variant only if its hash was frozen. `study.json`'s `frozen` map takes either.
