# Playtest Watcher Plan 2: Watch — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn one recorded session folder into `moments.json` (what the kid felt, when, and why) and `fixes.md`, using Meta models, runnable end to end with a fake model client before any credits are spent.

**Architecture:** A stage pipeline in `src/watch/`. Each stage reads files from the session folder and writes one output file; `npm run watch -- <sessionId>` runs stages in order and skips any stage whose output already exists (`--force <stage>` reruns one). All Meta calls go through one client (`src/meta/`) with a budget guard and a fake mode. Media work is ffmpeg via `child_process.execFile`.

**Tech Stack:** Node 26 (TypeScript run directly), Vitest, ffmpeg 8 at `/opt/homebrew/bin/ffmpeg`, `@meta-sam/parser` for SAM output.

Spec: `docs/superpowers/specs/2026-10-27-playtest-watcher-design.md` (sections 2, 3, 3a). API facts: `docs/meta-api-notes.md` — read it before Task 1.

## Global Constraints

- The watch stage reads only the session folder (`recordings/<id>/`) and writes only into it. It never reads `study.json` and never reaches into the recorder.
- Session folder inputs (from Plan 1): `session.json`, `manifest.json` (`{ startedAt, stoppedAt, tracks: { face|hands|screen|mic: { startedAt, mimeType, settings, bytes, chunks } } }`), `face.webm`, `hands.webm`, `screen.webm`, `mic.webm`, `events.jsonl` (`{ t, type, data: { kind, ... }, serverT }`). Any track may be missing; stages degrade instead of failing.
- **Session time** is milliseconds since `manifest.startedAt`. Events use `serverT - startedAt` (the server's clock, the same one the recorder used), never the game's own `t`.
- Moment labels: `confused | stuck | bored | frustrated | delighted | none`.
- Model ids: `muse-spark-1.2` for clips with audio, `muse-wonder-1.0` for text synthesis, `muse-voice-transcribe-1.0`, `sam-3.1`. The client throws on any id containing `contributor`.
- Budget: every paid call appends `{ at, model, kind, usd, usage }` to `recordings/spend.jsonl`. The client refuses a call once the running total reaches `PW_BUDGET_USD` (default 120). Live calls need `MODEL_API_KEY` in `.env.local` **and** `PW_LIVE=1`; otherwise the client is in fake mode. Default is fake.
- Uploaded files: always `expires_after[seconds]=3600`, deleted in a `finally` after the call.
- No kid names anywhere. Kids are letters.
- Tests never call the network or need real recordings; media tests generate tiny clips with ffmpeg's `lavfi` sources in a temp dir.

## File structure

```
src/meta/
  client.ts        createMetaClient({ live, apiKey, budgetUsd, spendLog, fetch? }) -> MetaClient
  fake.ts          deterministic fake responses for every method
  prices.ts        usd(model, usage) and per-unit prices from docs/meta-api-notes.md
src/watch/
  ffmpeg.ts        run(args), probeDurationMs(file)
  align.ts         stage 1: aligned.json + mp4 proxies + wav chunks
  transcribe.ts    stage 2: transcript.json
  loudness.ts      pure: rms windows from 16-bit PCM
  candidates.ts    pure + stage 3: candidates.json
  clips.ts         stage 4 helper: composite clip per candidate
  explain.ts       stage 4: moments.json
  fixes.ts         stage 5: fixes.md
  blur.ts          exported helper: blurFaces(inClip, outClip) via SAM
  run.ts           CLI: npm run watch -- <id> [--force stage] [--live]
tests/watch/       one test file per module, plus fixtures/
```

### Task 2: ffmpeg helpers and align stage

**Files:** `src/watch/ffmpeg.ts`, `src/watch/align.ts`. Test `tests/watch/align.test.ts`.

**Produces:** `align(dir: string): Promise<Aligned>`, writes `aligned.json`:
```ts
type Aligned = {
  t0: number; durationMs: number;
  tracks: Partial<Record<'face'|'hands'|'screen', { mp4: string; offsetMs: number; width: number; height: number }>>;
  audio?: { wavChunks: { file: string; startMs: number }[]; offsetMs: number };

```

- Events: parse `events.jsonl`, skip bad lines, `ms = serverT - t0`, `kind = data.kind ?? 'other'`, sorted by `ms`.
- `durationMs = manifest.stoppedAt - manifest.startedAt`.

### Task 3: Transcribe stage

**Files:** `src/watch/transcribe.ts`. Test `tests/watch/transcribe.test.ts`.

**Produces:** `transcribe(dir, client): Promise<Transcript>`, writes `transcript.json`:
```ts
type Transcript = { turns: { startMs: number; endMs: number; speaker: string; text: string; who: 'kid' | 'adult' | 'unknown' }[]; kidSpeaker: string | null };
```
- Each chunk is sent separately; turn times are shifted by `chunk.startMs + audio.offsetMs`. Speaker labels are per chunk, so they are re-keyed as `<chunkIndex>:<label>`.
- `who`: if `session.json` has `kidSpeaker` (an override), use it. Otherwise, per chunk, the speaker with the most total talk time is the kid (the kid thinks aloud; the adult mostly stays quiet), others are `adult`. With one speaker in a chunk, that speaker is `kid`.
- `keywords`: the game name plus distinctive words from event types (for example `molecule`, `blade`, `audit`).
- [ ] Failing tests with the fake client: two chunks shift correctly, re-keying works, the kid heuristic picks the longest talker, the override wins. Implement, test, commit.

Changed during build: `session.json` `kidSpeaker` is matched against the raw per-request label (`A`, `B`), since keys are re-keyed per chunk; `transcript.kidSpeaker` echoes the override or is null.

### Task 4: Loudness and candidates

**Files:** `src/watch/loudness.ts`, `src/watch/candidates.ts`. Test `tests/watch/candidates.test.ts`.

**Produces:**
```ts
export function rmsWindows(pcm: Int16Array, sampleRate: number, windowMs: number): number[];   // 0..1 per window
export type Candidate = { id: string; startMs: number; endMs: number; triggers: string[] };
export function findCandidates(input: { durationMs: number; events: Aligned['events']; turns: Transcript['turns']; rms: number[]; rmsWindowMs: number }): Candidate[];
export async function candidatesStage(dir: string): Promise<Candidate[]>;   // writes candidates.json
```
Triggers (each makes a window from `trigger - 6000` to `trigger + 8000`, clamped to the session):
- `fail` streaks: any `kind: fail` event (`fail:<type>`); a second `fail` within 10 s extends rather than adds.
- `retry`: the same `type` with `kind: attempt` 3+ times within 5 s.
- `idle`: an `idle` event, or a gap of 8 s+ between consecutive events.
- `quit`: `kind: quit`.
- `fast_progress`: two `progress` events of the same type less than 20 s apart (possible delight or boredom).
- `speech`: every `who: 'kid'` turn (window around its start).
- `loud`: an rms window above `max(0.2, 3 × median)` (laugh, groan).
- `sweep`: one every 60 s, so silent stretches are still looked at.
Overlapping or touching windows merge, and triggers are unioned. Ids are `c001`, `c002`... in time order. Windows longer than 40 s are split at 30 s.

- [ ] Failing tests (pure, no ffmpeg): rms of a full-scale square wave

Changed during build: `findCandidates` takes an optional `rmsOffsetMs` (the mic track's offset) so loud windows land on session time. Sweep windows are centred at 30 s, 90 s, ... (not 60 s, 120 s) so a short session still gets one. `idle` gaps are not counted before the first or after the last event. is ~1 and silence is 0; each trigger type produces a window; overlapping windows merge with unioned triggers; windows clamp at 0 and `durationMs`; a 90 s window splits; sweep windows appear every 60 s on an empty session; ids are sequential. Implement, test, commit.

### Task 5: Composite clips and the explain stage

**Files:** `src/watch/clips.ts`, `src/watch/explain.ts`. Test `tests/watch/explain.test.ts`.

**Produces:**
```ts
export async function compositeClip(dir: string, aligned: Aligned, c: Candidate, out: string): Promise<void>;
export type Moment = { id: string; startMs: number; endMs: number; triggers: string[]; label: 'confused'|'stuck'|'bored'|'frustrated'|'delighted'|'none'; confidence: number; evidence: { face: string; voice: string; hands: string; screen: string }; game_context: string; fix_hint: string; status: 'ok' | 'unanalyzed' };
export async function explainStage(dir: string, client: MetaClient, opts?: { concurrency?: number }): Promise<Moment[]>;  // writes moments.json
```
- Clip: face, hands and screen side by side (`hstack` after scaling each to 360 high; a missing track becomes a black `color` source), 5 fps, mic audio mixed in, H.264 + AAC MP4, trimmed to the candidate window using each track's `offsetMs`. Written to `clips/<id>.mp4` (inside the session folder, so gitignored).
- Prompt (one call per candidate, `muse-spark-1.2`, schema `moment`): what the three panels are, the game name, the kid's turns in the window, the events in the window as `+mm:ss.s type {data}` lines, and the label definitions. Ask for evidence per channel and a one-line fix hint written for the game's developer. Upload the clip, call, delete in `finally`.
- Failures: after the client's retries, the moment is written with `status: 'unanalyzed'`, `label: 'none'`, `confidence: 0`, and the stage continues.
- Concurrency default 4. Results keep candidate order.
- Re-running skips candidates already `ok` in an existing `moments.json` (cheap resume).

Changed during build: `compositeClip` takes the mic from `mic.webm` (not the wav chunks) and pads with silence if the window runs past the mic. Moments are matched for resume on id plus start/end, so a rerun of `candidates` doesn't reuse stale ones. produces an MP4 with three panels' width and the window's duration (±300 ms) and an audio stream; with `hands` missing it still produces a clip. `explainStage` with the fake client writes one moment per candidate, with a client that throws for `c002` writes `status: 'unanalyzed'` for it and keeps going, deletes every uploaded file (spy), and on rerun calls `respond` only for not-ok moments. ### Task 7: Face blur helper

**Files:** `src/watch/blur.ts`. Test `tests/watch/blur.test.ts`.

**Produces:** `blurFaces(client, inMp4: string, outMp4: string, opts?: { fps?: number }): Promise<{ frames: number; facesFound: number }>`.
- Re-encode to the target fps (default 5), upload, `segmentVideo(fileId, 'face')`, parse with `@meta-sam/parser` into per-frame boxes, then ffmpeg: for each frame's boxes, blur those regions (use a generated `sendcmd` file or a per-frame crop/boxblur/overlay chain; boxes padded 20%). Frames with no detection keep the **last known boxes for up to 1 s** so a missed frame doesn't flash a face. If SAM fails or finds nothing in a clip that came from the face camera, **throw**: an unblurred face must never be exported silently.
- Used only by the viewer/export step in Plan 3, never on whole sessions.

- [ ] Failing tests: the box-to-filter builder (pure)

Changed during build: no `sendcmd` or per-frame filter chain: boxes are rasterised to a gray8 mask stream piped to ffmpeg and applied with `maskedmerge` over a `boxblur` copy. Padding is 20% of the box size on each side. `@meta-sam/parser` 0.1.0 exists on npm and parses the documented format, but it rejects a box line with no mask, so the fake SAM response carries the README's real mask payload. `tests/watch/fixtures/sam-sample.txt` is the parser README's own example (real format), not output from a live call. Output is at the target fps (5), audio kept. pads, clamps to the frame, and carries boxes forward 1 s; the fake client returns a canned SAM response (store a real-format sample in `tests/watch/fixtures/sam-sample.txt`, built from the parser package's own test fixtures) and `blurFaces` produces an MP4; an empty SAM response throws. Implement, test, commit.

### Task 9 (stretch, after Plan 3 is on track): hands evidence

Changed during build (review fixes, 2026-10-27): an event's `ms` is `(t - gameClockSkewMs) - t0`, the game's own clock moved onto the server clock by the session's median `t - serverT`; `serverT` only sets that skew, since events arrive in 500 ms batches.
